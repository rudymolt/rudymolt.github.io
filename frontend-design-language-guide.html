Interaction language / V0.4 bootstrap

An editorial index, not a software dashboard.

The portal helps visitors scan Rudy's body of work, understand its direction, and open a destination. Paper's approved desktop and mobile artboards define the composition; this guide defines when each surface is appropriate.

Principles

  1. Editorial sequence over component grid. The page reads as numbered sections with deliberate alternating fields.
  2. Artwork carries identity. Large project images establish the visual direction; interface chrome stays restrained.
  3. One dominant action per item. The complete row or plate is the link. Do not add nested buttons.
  4. Metadata supports scanning. Small mono labels identify category and status but never compete with the title.
  5. Warm, engineered, specific. Parchment, oxblood, gold, Oxanium, and IBM Plex Mono replace generic SaaS styling.
  6. Responsive recomposition, not shrinkage. Mobile changes order and structure while preserving the same content and hierarchy.

Responsive contract

  • Desktop: 1440px reference artboard; wide editorial grids and side-by-side project compositions.
  • Tablet: preserve readable title and metadata columns; collapse before horizontal overflow appears.
  • Mobile: 390px reference artboard; vertical index rows, compact header, and reordered featured work.
  • The body must never overflow horizontally at 320px or wider.
  • The Ideas index shows numeric labels only: 01–04.
  • Text shared by desktop and mobile must be compared in both Paper artboards before implementation.
  • Interactive rows and plates are whole-surface links; isolated controls require a 44px target unless documented as compact metadata.

State and motion

  • Hover may colour a title ember or scale an image by about 1%; it must not reflow content.
  • Keyboard focus uses the documented ember outline and remains visible against soot and oxblood.
  • Reduced-motion preference disables smooth scrolling and transitions.
  • There are no loading, disabled, selected, modal, or URL-driven drawer states in the current static portal.

Change protocol

  1. Update the glossary if a new term or component is needed.
  2. Update the kitchen sink and render it at desktop, tablet, and mobile widths.
  3. Update this guide if the change introduces a new surface or interaction rule.
  4. Update the Paper artboards and obtain approval for structural or non-trivial visual changes.
  5. Implement the production page, run the CI gates, and verify GitHub Pages after deployment.
