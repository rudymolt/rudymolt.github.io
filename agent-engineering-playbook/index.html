Never written code? Two minutes of background

Eight words the guides lean on. Everything else is explained as you meet it.

Code
—
instructions that tell a computer exactly what to do. An app is thousands of lines of it.
Repo
—
the folder where a project's code and its full history live.
Database
—
where an app stores its information permanently, like spreadsheets the code can read and write.
Server
—
a computer running somewhere else that answers requests — book online, and a server records it.
UI
—
the part of the app you can see and touch: screens, buttons, forms.
Test
—
a small piece of code that automatically checks a bit of the app behaves as it should.
Deploy
—
putting a new version of the app live so real people can use it.
Production
—
the live version real users are using right now, as opposed to a private working copy.

What The AI Engineering Playbook Is

The AI Engineering Playbook is a way of working in which a person stays in charge while an AI coding agent does the building. Its instructions, templates, skills and scripts give both sides a shared process. They structure a coding session so the agent works inside a clear process: understand the task, agree the plan, break the work into small that can each be shown working on their own, build one slice at a time, review the result, test it, and ship only when the evidence is good enough.

V0.5 records the approved scope, checks host capabilities, separates building from fresh verification, and makes the delivery endpoint explicit. This is a process supported by tools and evidence, not a claim that a prompt makes every rule impossible to bypass.

How to brief the agent

Know what background, limits, signs of success, and proof to give the agent before it changes any code.

Process route map

Decide whether the next move is agreeing the plan, splitting the work up, building, reviewing, quality-checking, fixing a fault, shipping, or learning from how it went.

Verification discipline

Match the amount of checking to the risk, so small changes stay fast and important ones get tests, a check in the browser, a review, and a careful release.

Why It Exists

Claude, Codex, and similar coding agents can move very quickly, but speed creates a new problem: a vague request can lead to sprawling changes, a flimsy underlying design, no tests, and a result no one else can pick up later. The playbook exists to keep the person in charge of what to build and which trade-offs to make, while the agent handles the focused work of building it. It gives both sides a shared rhythm for writing code without turning every session into guesswork.

How To Start With Your Coding Agent

  1. Get the public v0.5.0 release and keep that checkout pinned to its tag. Point your agent at v0.5/AGENT-DIGEST.md, then run /ai-playbook-bootstrap-project for your project. Review its dry-run and UI, CI and host choices before it applies anything. The setup guide has the exact steps.
  2. Read How to drive the agent first. It follows one feature from first sentence to shipped code, and teaches the vocabulary every other page uses.
  3. Use the process map when you are unsure what kind of request you are making. It points the work to the right next step: agreeing the plan, splitting the work up, building, reviewing, quality-checking, fixing a fault, shipping, or a look back at how it went.
  4. For new features, use the alignment guide before code and the breakdown checker before building. The goal is one small slice that works end to end and can be shown off on its own, rather than a sweeping rewrite.
  5. While the agent is building, choose build one, build all, or build to <slice>; ask it to spell out any risky assumptions, and insist on tests or browser checks that fit the risk of the change.
  6. Before accepting the work, use the foundations, review, quality-check, and document lifecycle pages to check whether the result is easy to understand, easy to change later, tested, and ready to hand over or publish.

What Is Published Here

These human-facing V0.5 guides explain the playbook through linked, static HTML pages for people using coding agents. The public agent digest and stage Markdown are the operating source of truth. It includes this hub, the foundations guide, the 13-stage process map, focused alignment and breakdown explainers, the frontend-track guide, the document lifecycle guide, the practical agent-driving guide, the theory page that explains the reasoning behind the process, and a browsable glossary of every term the guides use.
