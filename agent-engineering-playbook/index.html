Never written code? Two minutes of background

Eight useful terms to start with. The guides explain other terms as they appear.

Code
—
instructions that tell a computer what to do.
Repo
—
short for repository: a project's files and their version history.
Database
—
an organised store of information that an app can read and update.
Server
—
a computer or program that responds to requests, such as saving an online booking.
UI
—
the part of the app you can see and touch: screens, buttons, forms.
Test
—
code that checks whether a particular behaviour works as expected.
Deploy
—
putting a new version of the app live so real people can use it.
Production
—
the live environment where people use the released app.

What is the playbook?

The Playbook is a practical guide and toolkit for building software with AI coding agents. It combines Markdown instructions, reusable project templates, agent skills and verification scripts that you apply to your own project. Your agent uses them to clarify the goal, plan small , build and test each one, review the result, and prepare it for release.

You bring the goals, acceptance criteria and judgement. The playbook gives your agent a repeatable workflow and records enough context for work to continue across sessions. Larger changes receive independent verification from a fresh agent context.

How to brief the agent

Give the agent the context, constraints and acceptance criteria it needs before implementation.

Find the right next step

Use the stage map to route a feature, bug, review or release through the appropriate workflow.

Check the result

Match verification to risk, from a focused check for a typo to tests, browser QA and independent review for larger changes.

Why use it?

A coding agent can produce a lot of code before anyone notices a misunderstanding. The playbook addresses three recurring problems: building the wrong thing, losing context between sessions, and accepting work without evidence. It helps you agree on success before implementation and check the result before release.

How to get started

  1. Get the public v0.5.0 release and keep that checkout pinned to its tag. Point your agent at v0.5/AGENT-DIGEST.md, then run /ai-playbook-bootstrap-project for your project. Review its dry-run and UI, CI and host choices before it applies anything. The setup guide has the exact steps.
  2. Read How to drive the agent for practical examples. It explains what to ask, which decisions need your input, and what evidence to expect.
  3. Use the process map when you are unsure what kind of request you are making. It points the work to the right next step: agreeing the plan, splitting the work up, building, reviewing, quality-checking, fixing a fault, shipping, or a look back at how it went.
  4. For new features, use the alignment guide before code and the breakdown checker before building. The goal is one small slice that works end to end and can be shown off on its own, rather than a sweeping rewrite.
  5. While the agent is building, choose build one, build all, or build to <slice>; ask it to spell out any risky assumptions, and insist on tests or browser checks that fit the risk of the change.
  6. Before accepting the work, use the foundations, review, quality-check, and document lifecycle pages to check whether the result is easy to understand, easy to change later, tested, and ready to hand over or publish.

About these guides

These guides explain the public V0.5 playbook for people using coding agents. Start with the practical guide, use the process map to find a stage, and consult the theory and reference pages for more detail. Agents should start with the agent digest and follow its links to the authoritative Markdown instructions.

Acknowledgements

The playbook brings together ideas and tools shared openly by these projects:

  • Matt Pocock's skills provide focused workflows for planning, specifications, testing and code design.
  • Garry Tan's gstack contributes product, design, review, QA and delivery workflows.
  • Lauren Tan (@poteto)'s pstack provides investigation and verification skills adapted in the playbook.
  • Intelligent Internet's Zenith informed the approach to autonomous loops, independent verification and stopping conditions. It is inspiration rather than a dependency.

Adapted skills retain their upstream notices. The skills guide explains how these sources fit into the workflow.
